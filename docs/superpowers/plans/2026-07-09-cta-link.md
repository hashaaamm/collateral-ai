# CTA Link Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users supply a CTA destination URL on the create page; store it on the material, stamp it into the generated JSON, and render the email-preview CTA as a clickable link.

**Architecture:** The CTA link is a user-supplied URL, never LLM-generated. Backend adds a `cta_link` URLField to `MarketingMaterial`, accepts it on create, and deterministically stamps it into `output_json["article"]["cta_url"]` after generation (the LLM prompt/schema are untouched). Frontend collects it in the create wizard and renders the CTA as an `<a href>` when a URL is present, falling back to the current non-clickable `<div>`.

**Tech Stack:** Django + DRF, pytest; React + TanStack Router/Query + Vite, vitest; openapi-typescript-generated API types.

## Global Constraints

- CTA link is **optional** everywhere — blank must behave exactly as today (no `cta_url` key, non-clickable CTA).
- The link is **never** sent to the LLM (no changes to `prompts.py` or `schema.py`).
- The link is validated as a well-formed URL by Django/DRF `URLField`; blank is allowed.
- JSON shape: add sibling `article.cta_url` — do **not** change `article.cta` (stays the LLM label string).
- Follow existing code style; no unrelated refactoring.

    def _stamp(self, output: dict, template, material) -> dict:
        """template_id and theme are template-owned — never trusted from the model.

        return output
