# CTA link for marketing materials

**Date:** 2026-07-09
**Status:** Approved

## Problem

Marketing materials render a call-to-action (CTA), but the CTA is a plain text
string at every layer — generated by the LLM and rendered as a non-clickable
`<div>`. There is no destination URL, so the CTA button in the email preview
and the generated JSON cannot actually link anywhere.

We need to collect a CTA link (destination URL) on the create page and use it as
the `href` of the CTA button in the email preview and in the generated JSON.

## Approach

The CTA link is a **user-supplied destination URL**, not LLM-generated content.
The LLM continues to generate only the CTA *label text* (`article.cta`). The URL
is a deterministic passthrough: the backend validates it, stores it on the
material, and stamps it into the generated JSON after generation. It is **never**
sent to the LLM (not in the prompt, not in the response schema).

JSON shape: add a sibling field `article.cta_url` alongside the existing
`article.cta` string. This keeps the current string contract intact so no
existing render/validation sites break.

The field is **optional**. When blank, behavior is identical to today.

## Backend changes

- **Model** (`backend/collateral_ai/materials/models.py`): add
  `cta_link = models.URLField(blank=True, default="")` to `MarketingMaterial`.
  `URLField` provides http(s) validation. Include the migration.
- **Serializers** (`backend/collateral_ai/materials/api/serializers.py`):
  - `MaterialCreateSerializer`: add optional `cta_link` field.
  - `MaterialDetailSerializer`: expose `cta_link`.
  - `MaterialUpdateSerializer`: allow updating `cta_link`.
  - DRF `URLField` validation rejects malformed URLs, allows blank.
- **Generation stamping** (`backend/collateral_ai/materials/generation/service.py`,
  `_stamp`): after the LLM returns, if `material.cta_link` is set, write it into
  `output_json["article"]["cta_url"]`. Leave `prompts.py` and `schema.py`
  untouched — the link never reaches the model.

## Frontend changes

- **Create wizard** (`frontend/src/routes/create.tsx`): add an optional "CTA link"
  URL input in step 2 (Prompt), near the `ctaStyle` control, with `type="url"`
  for light client-side validation. Include `cta_link` in the POST body.
- **API types** (`frontend/src/lib/api/materials.ts`): add `cta_link?: string` to
  the material type and `cta_url?: string` to `OutputJson.article`.
- **Preview** (`frontend/src/components/newsletter-preview.tsx`): if
  `output.article.cta_url` is present, render the CTA block as
  `<a href={cta_url} target="_blank" rel="noopener noreferrer">`; otherwise keep
  the current non-clickable `<div>`.

## Backward compatibility

Existing materials have an empty `cta_link` → no `cta_url` in `output_json` →
the preview renders exactly as today. No data migration of existing rows needed
beyond adding the nullable/blank column.

## Testing

- Backend serializer test: accepts a valid URL, rejects a malformed one, allows
  blank.
- Backend stamping test: when `cta_link` is set, it lands in
  `output_json["article"]["cta_url"]` after generation.
- Frontend preview test: renders an `<a>` when `cta_url` is present, a `<div>`
  when absent.

## Out of scope

- LLM-driven CTA URL selection (the URL is deterministic, user-provided).
- Changing `article.cta` into a structured object.
- Per-template default CTA links.
